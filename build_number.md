# LiberNT-LDW build number

One build number per integration landed on `leeway/main`. Owner decision of 2026-11-08: every integration (an upstream sync, a batch or a feature merge pushed to `leeway/main`) increments the build number by one; a large integration may take two or three. Direct hotfix commits pushed to `leeway/main` between integrations ride with the next build and do not increment it.

The build number is the human counter of the tree. The full identity of a binary stays the LBI label `seq.rev.archtype.channel.stamp` (WS-B): the LBI sequence is allocated per build attempt in the ledger `LeewayOpenSoftware/leeway-lbi-ledger` and is never reused, while the build number below names the integration the attempt was built from. From the next allocation on, the ledger record and `lbi.json` carry `integration_build`, so a label resolves to its row in this table.

Dates are the commit dates of the landing tip (UTC-3). Commits are abbreviated to 11 characters. "Direct" rows are hotfixes pushed outside an integration; they carry no number. The newest integration is on top.

## How the numbers were derived

- The list is the first-parent history of `leeway/main` at `a29687ab92e` (`git log --first-parent`), read as landing events: every integration branch fast-forwarded onto main (`leeway/integration-1029` to `-1032`), every batch recorded in `shared/libernt/ledger/LEDGER.md` and `BRANCH-TRIAGE.md` (batches 1 to 7 with their main tips), every upstream sync merge, and the sync-by-cherry-pick runs 1104 to 1106 (`shared/libernt/upstream-review`). Author dates of cherry-picked commits are older than their landing; the dates above are those of the landing tips.
- Build 1 is the first upstream sync (2026-10-28), the first integration after the fork. Counting one per landing gives `leeway/main` `a29687ab92e` = **build 16**. Today's integration is large (eight branches, the statistics work, the NTFS shutdown flush, the network fixes) and takes **+3**, so it lands as **build 19**.
- Where the ledger of LBI sequences and a per-integration count conflict, this file wins for the build number and the ledger wins for the sequence:
  1. The build number counts integrations landed on `leeway/main`, starting at 1, +1 per landing (+2 or +3 for a large one on the owner's call); hotfix commits pushed directly ride with the next build.
  2. The LBI sequence (`refs/lbi/seq/N`, 32 allocated so far, all on LBI test trees, none on a `leeway/main` tip) counts build attempts across every channel and never maps one to one onto integrations; it is not restarted, offset or aligned to this table.
  3. The link between the two is recorded at allocation time: `integration_build` in the ledger record and in `lbi.json` names the build of the `leeway/main` tip the attempt was built from (or the build it is pending for, on an integration branch).
